# 本组路线：授权状态驱动

## 一、共同的部分

你和陈良彬题目相同，所以两边的**契约**要对齐，否则结果没法互相比对：

| 项目 | 取值 |
| --- | --- |
| 目标 | 本地教学文档服务模拟器 |
| 用户 | 两名虚构用户 A、B，另有匿名与已撤权身份 |
| 资源 | 两份文档及各自附件 |
| 检查 | 六项注册检查 |
| 证据 | 每次运行独立目录，含元数据、事件流水、报告与哈希 |
| 结论 | 确认问题 / 在已检查范围内未确认 / 证据不足 |
| 预算 | 检查次数、决策轮数、逻辑时间各有上限，单并发不重试 |
| 结论状态 | 未执行、被拒绝、证据不足三者分开记录 |

这些是**共同语言**，两边各自实现，不互相抄代码。

## 二、你的不同路线

陈良彬的路线是**调度策略对照**：固定流程 vs 模型动态调度，比较的是「谁来选下一项检查」。

你的路线是**授权状态驱动**：把「授权」本身当成一等对象，比较的是「授权怎么进来、什么时候生效」。

### 对照实验

| | 策略 S：静态授权快照 | 策略 T：动态授权源 |
| --- | --- | --- |
| 授权来源 | 任务开始时读一次，全程固定 | 版本化的授权事件源，随时可更新 |
| 撤权生效 | 不生效，只能等任务结束 | 下一次动作前即生效 |
| 在途动作 | 忽略 | 记录边界，不承诺瞬时取消 |
| 重新授权 | 不支持，需新任务 | 支持，从快照恢复 |
| 拒绝记录 | 保留 | 保留，且不可被历史覆盖 |

两种策略共用同一套注册表、执行器、证据格式和结论判定，只有授权来源不同。
这一点和搭档的对照实验结构一致，所以你俩的审查方法可以互相套用。

### 四个要答的问题

1. 动作开始前，授权是按最新版本判定的吗？
2. 撤权发生在动作之前，后续调度是否立即停止？
3. 撤权发生在动作之后，边界怎么记录、未覆盖怎么说明？
4. 重新授权后能否从快照恢复，且历史拒绝记录不被改写？

## 三、首版边界

**做**：注册表与独立控制器、六项检查、静态与动态两种授权策略、原始证据落盘、
三类结论、覆盖与停止说明、运行中撤权、重新授权与恢复。

**不做**：任意 URL 或任意 Shell 执行、真实外网目标、真实资产、生产凭据、
多 Agent 自治、瞬时取消承诺、真实模型调度（那是对手的路线）。

## 四、和对抗组的关系

你审他时，按他的调度对照契约适配 2—3 项检查；他审你时，按你的授权契约看撤权与恢复。
两边都不直接比较绝对性能或成本，只比「结论是否有证据支持、边界是否说清、未覆盖是否如实」。
