# 状态模型与撤权边界

## 检查任务状态

```text
Proposed
   |  控制器准入（读授权范围）
   |-- 拒绝 --> Denied（记录理由与当时的授权版本，不执行）
   `-- 放行 --> Executing
                  |
                  `--> Observed --> Classified（CONFIRMED / NOT_CONFIRMED / INCONCLUSIVE）
```

## 授权范围状态

```text
authorized --撤权事件--> revoked
```

`static_snapshot`：撤权事件被拒，状态不变。
`dynamic_source`：撤权事件版本正确时立即生效，影响下一次准入。

## 三个不变量

1. 注册范围外不执行，且不写进报告当安全。
2. 证据不足不通过。
3. 停止后不启动新动作。

## 撤权时点与边界

| 时点 | 期望行为 |
| --- | --- |
| 动作开始前撤权 | 下一次准入即被拒绝，不执行 |
| 动作执行中撤权 | 本次动作按其结果完成并记录；边界写入 `boundary_notes` |
| 动作完成后撤权 | 已产生的证据保留，后续检查按新范围准入 |
| 重新授权 | 由有权主体发起新事件；历史拒绝记录不得被覆盖 |

本实现不承诺瞬时取消在途动作，只如实记录边界。

## 身份状态与授权范围的区别

这是本路线最容易混淆的一点：

- 身份状态是**被测系统的输入**。`revoked_A` 返回 401 说明被测系统正确拒绝了它。
- 授权范围是**本组自己的许可**。撤掉 T05 的授权意味着我们不再被允许做这项检查。

两者独立：撤掉 T05 的授权不会改变 `revoked_A` 这个身份，只会让 T05 不再执行、
并出现在未覆盖列表中。
